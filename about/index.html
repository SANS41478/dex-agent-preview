大多数 Agent 工具只给你一个输入框和一个输出流。Dex AGENT 想把中间那层打开：插件怎么挂载、工具怎么被调用、为什么这一步花了四秒、失败从哪一步开始传播。

PRINCIPLES

四条原则

来自设计系统 / 任何视觉决策都要能解释语义

01

视觉即解释

每个视觉编码对应一个可解释的语义；没有“为了好看”的第三种蓝。

02

动效承载信息

动效表达状态变化，不是循环播放的装饰。脉冲只用于“仍在运行”。

03

空间记忆优于面板切换

布局稳定，聚焦子图，不重新排列世界。你调过的宽度会被记住。

04

性能即体验

50fps 是及格线。宁可少一层阴影，也不接受掉帧。

BOUNDARY

是什么，不是什么。

产品边界 / 与 IDE、云端服务的区别

IS可实际执行编码任务的 Agent 工作台。选择工作区、创建会话、提交任务、看到回复。
IS可观察、可拆解、可扩展的观测层。3D 图谱、DAG、时间线与联动。
IS本地优先的桌面应用。工作区与会话留在本机。
NOT不是 IDE 替代品。不追求编辑器级 diff、补全与重构。
NOT不是云端同步服务。没有账号、云盘与远程工作区。
NOT不是多 Agent 编排器。先把一个 Agent 看清楚。
ARCHITECTURE

结构

Cordis 插件运行时 / 桥接层 / Electron + React

Cordis 插件运行时提供插件树与事件；桥接层把它们映射为图数据与执行流；Electron + React 负责桌面壳与观测界面。

  • RUNTIME不修改运行时核心。扩展以插件形式挂载。
  • BRIDGE桥接只做映射。不重复实现插件树与事件驱动。
  • OBSERVE前端通过注册机制扩展。新的可视化类型不需要改核心。
