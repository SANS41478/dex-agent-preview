### Hero

- 副标题：`三个视角，同一份运行状态：结构、过程、时间。`

### 图谱

- H2：`结构是空间的。`
- 正文：`插件不是列表里的一行，而是一个有位置、有依赖、有状态的节点。图谱让“它由什么构成”变成可以走进去的空间。`
- 编码表：
  - `形状` → `插件类型`
  - `大小` → `活跃度`
  - `颜色` → `状态`
  - `边宽` → `调用频率`
  - `动效` → `状态变化`
- 交互列表：`缩放 / 旋转 / 平移`、`点击节点查看详情`、`搜索定位`、`聚焦子图`、`按类型过滤`、`视角与缩放记忆`
- 图注：`节点类型与状态三重编码：颜色、光环、标签文字。`

### 执行流

- H2：`过程是因果的。`
- 正文：`Step 是节点，Tool Call 是节点里的证据。失败不是一行红字，而是一条向上传播的路径。`
- 要点：
  - `Step 默认紧凑：序号、状态、一行推理摘要`
  - `点击展开 Tool Call chip，局部重排`
  - `失败节点变红，向上传播到 Turn`
  - `详情面板：错误原因、堆栈、推理文本、入参与返回`
- 图注：`DAG 中的 Step 与 Tool Call · 失败路径可定位`

### 时间线

- H2：`时间是可回退的。`
- 正文：`按时间排列事件流，与 DAG 联动。回退到任意 Step，查看当时的上下文；回放一次执行，而不是猜它发生过什么。`
- 图注：`时间线 · 实时与回放共用同一套事件`

### 联动

- H2：`三个视角，一份状态。`
- 正文：`点击 DAG 里的 Step，图谱中对应插件高亮；选中图谱里的工具节点，DAG 过滤出调用它的 Step。折叠不丢状态，展开立即呈现。`
- 层级：
  - `L1 状态同步：高亮与选中`
  - `L2 过滤联动：按工具筛选 Step`
  - `L3 空间导航：相机飞行到节点`
- 示意按钮：`点击 Step 03` / `重置`

### 性能

- H2：`先过性能关，再谈视觉。`
- 正文：`500 节点是基准线。图谱采用增量更新、LOD 降级与稳定的引脚策略；交互掉帧，再好的视觉编码也失效。`
- 数据：`500 节点` / `101fps` / `p95 12.5ms`
- 脚注：`本机开发环境，5 秒采样；实际取决于硬件与场景。`

## 关于页 `/about/`

### Hero

- 小标：`Open the loop.`
- H1：`打开回路。`
- 副标题：`大多数 Agent 工具只给你一个输入框和一个输出流。Dex AGENT 想把中间那层打开。`
- 正文：`插件怎么挂载、工具怎么被调用、为什么这一步花了四秒、失败从哪一步开始传播——这些不该只存在于日志里。`

### 原则

- H2：`四条原则`
- `视觉即解释`：每个视觉编码对应一个可解释的语义；没有“为了好看”的第三种蓝。
- `动效承载信息`：动效表达状态变化，不是循环播放的装饰。
- `空间记忆优于面板切换`：布局稳定，聚焦子图，不重新排列世界。
- `性能即体验`：50fps 是及格线；宁可少一层阴影，也不接受掉帧。

### 是什么 / 不是什么

- 是：`可实际执行编码任务的 Agent 工作台`
- 是：`可观察、可拆解、可扩展的桌面观测层`
- 不是：`IDE 替代品`
- 不是：`云端同步服务`
- 不是：`多 Agent 编排器`
- 不是：`只读日志查看器`

### 架构

- H2：`结构`
- 正文：`Cordis 插件运行时提供插件树与事件；桥接层把它们映射为图数据与执行流；Electron + React 负责桌面壳与观测界面。`
- 层级：`Cordis 插件运行时` → `graph bridge / trace bridge` → `WebSocket` → `Electron + React`
- 说明：`不修改运行时核心；扩展以插件形式挂载。`
